## A-F 残留检查

- **A1/A3 分组**:fileconv 按域(archive/fs_util)非批次;无溯源标签。
- **A2/C9 版本字眼**:注释零版本号(zip/tar 版本仅在 Cargo.toml,非文档正文)。
- **B4 装饰**:无 `====` 横幅;单行区隔。
- **B5/B6/B7**:无 benchmark 角标/match 冗余/HACK guard。
- **C8 模块隔离**:archive.rs/fs_util.rs 各写自己文件,lib.rs 仅注册。
- **C10 死字段**:ArchiveFormat 四变体全消费(Zip/Tar/TarGz/Gz)。
- **D11 校验对应**:GZ 多文件→InvalidInput;路径遍历→InvalidInput;格式不识别→InvalidInput。
- **D13 ToolError 单一**:复用 core 定义,无 drift。
- **E15/E16**:中文注释;无 unsafe/asm(flate2/zip/tar 均安全封装)。
- **TODO 残留**:零。
- **手写压缩**:无(全用 zip/tar/flate2 成熟 crate)。

## 重构记录(纯净改进)

实现中发现 CLI `io.rs` 与 GUI `commands.rs` 重复了 `write_bytes_create_new`/`write_bytes_safe`/`resolve_extract_dir` + extract 写入循环(~60 行)。重构:上提到 `fileconv::fs_util`(extract_to_dir/compress_files/convert_file),CLI/GUI 变薄封装,消除重复(DRY)。

## 待人工确认

- **GUI 编译验证**:本机 `cargo check -p nextool-gui` 触发 `windows` 0.61.3 crate STATUS_STACK_BUFFER_OVERRUN(rustc 栈溢出 ICE,内存受限,已知限制)。GUI 代码遵循既有 49 命令精确模式(薄封装 + dialog 插件 + capabilities),正确性留 CI `tauri-build` 三平台验证。
- **zip 默认依赖体积**:zip 2.4.2 默认拉入 bzip2/xz2/zstd/lzma-rs/zopfli/deflate64(多压缩后端)。release 体积待测;若超 8MB,改 `zip = { default-features = false, features = ["deflate"] }` 只留 deflate(用已有 flate2)。
- **number 参数**:fileconv command 的 number 参数(无,均 string/select)不涉及 serde string→number 问题。
- **拖拽/进度**:未做(预留),大归档批量转换时后续加 `onDragDropEvent` + `Channel<ConvertEvent>`。
