## 核心发现:GUI RSA 命令缺失(已修复)

**问题:** `src/tools.ts` 列出 49 个工具(含 `rsa_encrypt`/`rsa_decrypt`),但 `crates/tauri-app/src/commands.rs` 与 `lib.rs` 的 `generate_handler!` 仅注册 47 个(缺这两个)。core 与 CLI 均已实现(`crypto.rs::rsa_encrypt/rsa_decrypt`、`crypto_cmd.rs::RsaEncrypt/RsaDecrypt`),唯独 Tauri command 层漏注册 → **GUI 的 RSA 加密/解密按钮 invoke 必运行时失败**("command not found")。

**根因:** 此前 `docs/audit/2026-08-21-gui.md` 称"47 个 tools.ts id == commands.rs pub fn == lib.rs generate_handler,三处集合完全相等"为误判——未察觉 tools.ts 的 crypto 段有 7 项(aes×2/rsa_keygen/rsa_encrypt/rsa_decrypt/pbkdf2/argon2)而 command 层仅 5 项。

**修复:**
- `commands.rs` 补 `rsa_encrypt(input, pub_pem)`、`rsa_decrypt(input, priv_pem)` 两个 `#[tauri::command]` 薄封装,转发 `nextool_core::rsa_encrypt/rsa_decrypt`。
- `lib.rs` 的 `use` 块与 `generate_handler!` 均补 `rsa_decrypt, rsa_encrypt`。
- 参数映射核对:tools.ts `pubPem`/`privPem`(camelCase)→ Tauri 转 `pub_pem`/`priv_pem` → 匹配 core 签名。

**结果:** tools.ts(49)== commands.rs(49)== lib.rs generate_handler(49)== api.md(49 行),四处集合一致。
